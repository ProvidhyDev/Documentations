Federated Identity & eSewa Miniapps — Complete Documentation

Reverse-engineered from the production codebase (E:\Work) on 2026-11-03. Every claim in this documentation set is backed by source file:line citations. Nothing is invented — unknowns are explicitly labeled in each doc's "Unknowns" section.

What this is

A complete technical + business documentation of the federated identity miniapp surface of the Providhy multi-tenant ERP platform: how the eSewa merchant/customer miniapp authenticates against IAM, and how it talks to Sales, CDXE, Projectmaster, Payment (eSewa), TMS, Configuration, Events, and back again — endpoint by endpoint, call by call.

Written so that both audiences get what they need:

  • Non-technical reader: sections "Business overview" and "Business process walkthrough" in every doc, plus 01-overview. Read those first.
  • Technical reader: endpoint catalogs, per-endpoint flow traces with file:line refs, ER diagrams, sequence diagrams, cross-service call maps.

Scope (as requested)

  • miniapp apps inside: Sales, CDXE-REBOOT, ERP-Projectmaster, other apps with a miniapp surface (TMS, Events)
  • federated_identity app in IAM-Backend
  • payment services esewa app in Payment-Service (+ the miniapp-esewa frontend that drives it)
  • certain portions of TMS: only the registration/onboarding and configuration parts used by the miniapp (not the full tenant-management admin surface)
  • Configuration-Service service_configuration (the federated-authenticated tenant config)
  • Every endpoint authenticated with FederatedIdentityAuthentication, plus the service-to-service internal endpoints those flows call, traced from the exposed endpoint down to the leaf call.

Out of scope (noted in docs where they appear as boundaries): Website-Service (terms page), Package service (module catalog), Purchase/Accounting/PMS/Document, the main ERP frontends, CMS surface, heimer_auth's full admin user surface.

Key facts (verified)

  • Platform: Django 5 + DRF microservices, one Postgres DB per service, Redis, Celery, Kafka (kafka_producer consumer repos), Prometheus metrics.
  • Public (dev) hosts: dev-iam-api.providhy.com, dev-sales-api.providhy.com, dev-cdxe-api.providhy.com, dev-projectmaster-api.providhy.com, dev-payment-api.providhy.com, dev-tms-api.providhy.com, dev-configuration-api.providhy.com, dev-events-api.providhy.com, dev-package-api.providhy.com ...
  • Internal (docker) hosts: http://iam:8000, http://sales:8000, http://cdxe:8000, ...
  • Frontend: miniapp-esewa (Next.js App Router, TypeScript) — E:\Work\miniapp-esewa.
  • Auth: federated JWT (HS256) issued by IAM external/token/, re-verified against IAM per request + X-MINIAPP-TOTP header; internal service calls use a shared internal password.
  • Miniapp URL mounts: Sales/CDXE/Projectmaster/TMS under /api/miniapp/, Payment-Service esewa app under /api/esewa/, IAM federated app under /api/external/, Configuration under /api/service-configuration/, TMS tenant endpoints under /api/tenant/, events under /api/notification/ and activity log mounts (see 13-api-catalog).
