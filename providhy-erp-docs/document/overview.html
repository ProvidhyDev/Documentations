Document Service

The Document-Service is the central file/document store for ProvidhyERP: tenant logos and profiles, per-module attachment documents (invoices, orders, etc.), CMS-managed documents, and website/agent documents. Other services call it internally to store or delete tenant documents.

Repo: Document-Service @ branch f1-production, SHA 1794bdd8. Routes on f1-production: 22, under /api/document/ plus one /api/dashboard/ route. Source: config/urls.py, document_manager/urls.py, document_manager/views.py, dashboard/views.py @ 1794bdd8.

Key flows (verified)

Upload / replace (endpoint 1)

  • View DocumentHandler - document_manager/views.py:522 (IAM auth :523).
  • multipart POST with files field document; query params entry_type (required), document_type, document_name (views.py:539-543).
  • Tenant-root guard: tenant_logo / tenant_profile uploads require request.tenant_root (views.py:544-551).
  • Existing documents for the same (tenant, entry_type, entry_id, document_type, tenant_root) are deleted and replaced inside a transaction (views.py:572-643).
  • Response 200 { document_id, url } (views.py:644-650); 400 on missing entry_type/root access; 204 when no file present (views.py:561-565).
  • Endpoint 2 (DocumentHandlerInternal, views.py:653-655) inherits the entire handler with InternalRequestAuthentication instead of IAM.

CMS endpoints (8-11)

  • CMSIAMAuthenticationBackend on cms-module (views.py:332), cms-document-list (views.py:475), add-cms-document (views.py:153), add-cms-bulk-document (views.py:251 - class-level auth verified; bulk body unverified in detail).
  • These are the CMS-frontend-facing routes that let content managers attach/manage tenant and website documents.

Dual-auth record-entry-document (19)

  • FeatureEntryDocumentView switches authentication per request: internal header present -> InternalRequestAuthentication, otherwise IAMAuthenticationBackend (views.py:1276, 1283-1285) - lets both the ERP frontend and other services record entry documents.

Frontend usage

apps-frontend references 8/22 latest Document routes (fe_usage.json) - the IAM upload/list/delete flows; the internal and CMS routes are consumed by other services and the CMS frontend respectively.
