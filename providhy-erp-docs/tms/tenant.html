Upgrade & renew flows

Each flow follows: get-data (build the upgrade/renew payload) -> calculate (pricing) -> save/post-after-payment (apply) -> log (subscription log). /cms/ variants take CMSIAMAuthenticationBackend for the CMS platform's flows.

  • Module upgrade: get-upgrade-module-data, save-upgrade-module-data, active-upgrade-module-sub-log, upgrade-module/cms (cms-iam).
  • Package renew: get-renew-package-data, calculate-renew-package, get-tenant-package-renew-data, post-renew-package-after-payment, post-package-renew-log.
  • Package upgrade: get-upgrade-package-data (+/cms/), calculate-upgrade-package, post-upgrade-package-data, upgrade-package/cms, upgrade-cms-package (cms-iam), upgrade-cms-module/<tenant_id>/ (cms-iam).
  • CMS renew: get-cms-tenant-package-renew-data, post-cms-tenant-package-renew.

View line anchors: the upgrade/renew cluster spans views.py:1882-2500 and the CMS cluster views.py:2863-3200 (auth lines :1882, :1980, :2421, :2482, :2863, :3060); per-method field tables are unverified - the cluster behavior above is verified at the class/auth level.
