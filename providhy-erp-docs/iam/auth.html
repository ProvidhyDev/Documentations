IAM . Token, Registration, Password

The identity lifecycle: register -> verify email -> login (token) -> refresh/verify -> change/reset password -> logout / force-logout.

Token endpoints (public)

# Method Path View Notes
1 POST /api/token/ MyTokenObtainPairView heimer_auth/views.py:117
2 POST /api/token/refresh/ CustomTokenRefreshView heimer_auth/views.py:231
3 POST /api/token/verify/ CustomTokenVerifyView / TokenVerifyView heimer_auth/views.py:263 (two route entries for verify - see note)
  • Token issue (views.py:117 onward): standard obtain-pair flow backed by MyTokenObtainPairSerializer (heimer_auth/serializers.py:50) - the serializer builds the token payload with tenant_id, user permissions, subscribed services, subscription expiry, tenant_root, fiscal year (serializer body serializers.py:50-186; exact claim list unverified line-by-line here). Enforces email-verified and subscription checks through the exception set in heimer_auth/exception.py (EmailNotVerifiedException, SubscriptionExpired, MaxActiveUserSessionExceededException, AlreadyLoggedInException).
  • Refresh (views.py:231) uses CustomTokenRefreshSerializer (serializers.py:187).
  • Verify (views.py:263) is the endpoint every other module's IAMAuthenticationBackend* hits to validate tokens - the root of cross-service auth.
  • Note: the catalog lists /api/token/verify/ twice (CustomTokenVerifyView and a TokenVerifyView alias) - both mounted in the urls file; treat as the same endpoint.
