Sales . Quotation

Quotation lifecycle: create -> submit for approval -> approve / reject / cancel -> (optionally) convert to a sales order. Approval flows are tenant-configured (basic vs custom) by the Configuration service.

All routes below are relative to the service root; on the live service they sit under /api/sales/quotation/. Source: sales/sales_quotation/urls.py, views.py, serializers.py @ d07a3d4c.

Endpoint map

2 GET /quotation/detail/ Quotation detail IAM + VIEW

10 GET /quotation/search/select/ Search for pickers / embedded selects IAM (no feature check)

1. POST /quotation/ - create

  • View: SalesQuotationListCreate - sales/sales_quotation/views.py:34 (route urls.py:6).
  • Auth: IAMAuthenticationBackendSales + HasPermission (views.py:33-39); POST requires action ADD_EDIT (set in initial(), views.py:41-47).
  • Request (JSON):
    • quotation_date (date) - required.
    • valid_till (date) - required.
    • customer (customer id) - required.
    • items (array) - required; each item needs product_id, quantity, uom (validated at views.py:52-57).
    • Fiscal year is injected from the authenticated request, not the client (views.py:63).
  • Processing: serialized by SalesQuotationWriteOnlySerializer with tenant + user context (views.py:64-68).
  • Response: 201 { id, message } on success; 400 { error } with serializer errors (views.py:69-78).
  • Side effects: none observed in the create path (no kafka.call_kafka here).

2/3. GET / POST /quotation/detail// - detail & update

  • View: SalesQuotationUpdate - views.py:106 (routes urls.py:7-11).
  • Auth: IAM + HasPermission; GET -> VIEW, POST -> ADD_EDIT (views.py:108-117).
  • GET: loads the record scoped to the authenticated tenant (get_object, views.py:26-30); applies user-level row visibility via helper.user_filter (row-visibility rules live in the shared dashboard helper - unverified here); returns SalesQuotationReadOnlySerializer data, 404 with a not-found error otherwise (views.py:119-137).
  • POST: updates the quotation in place with the write serializer; same tenant scoping (views.py:139).

4. GET /quotation/detail-no-perm// - detail without permission

  • View: SalesQuotationGetNoPerm - views.py:81 (route urls.py:12-16).
  • Auth: IAM only - no HasPermission feature check; any authenticated tenant user who knows the id can read it. Used so other sales screens (orders, invoices) can embed a quotation header.
  • Same tenant scoping + user_filter + read-only serializer as endpoint 2 (views.py:84-102).

5. POST /quotation/delete// - delete

  • View: SalesQuotationDelete - views.py:174 (route urls.py:17-21).
  • Auth: IAM + HasPermission, action ADD_EDIT (views.py:175-178).
  • Behavior: deletes the record within a tenant-scoped lookup (views.py:180-208). Exact guard rules (e.g. whether submitted/approved quotations are deletable) - unverified beyond the range shown.

6. POST /quotation/status// - status change (approval workflow)

  • View: SalesQuotationStatusChange - views.py:211 (route urls.py:22-26); entry point post() at views.py:330.
  • Auth: IAM + HasPermission; action set by target status in initial() (views.py:214-221).
  • Request: { status, comment?, approval_user? }.
  • Flow (views.py:330-352):
    1. Loads the tenant's approval-work configuration from the Configuration service (send_requests.get_configuration, views.py:338-343).
    2. Title BASIC -> _handle_basic_flow; title CUSTOM -> _handle_custom_flow; anything else -> 503 service unavailable (views.py:344-352).
  • Sub-actions (basic flow):
    • Submit for approval (views.py:354-418): rejects self-approval (views.py:357); validates all line products via the Inventory service (helper.product_validation, views.py:368); validates the approval user via IAM (views.py:372); sets approval_user, submit_for_approval_date, comment, status; clears prior rejection fields if previously rejected (views.py:380); sends a notification (views.py:384), writes an activity log (views.py:391), emits Kafka record type SALES_QUOTATION_SUBMIT_FOR_APPROVAL_RECORD (views.py:398-409).
    • Approve (views.py:420-467): re-validates products, sets approved_by/date/date_time/comment, saves, activity log, Kafka SALES_QUOTATION_APPROVAL_RECORD.
    • Cancel (views.py:469-514): re-validates products, sets cancelled_by/date/comment, activity log, Kafka SALES_QUOTATION_CANCEL.
  • Response: 200 { message } per outcome; 400 on validation errors.

7. POST /quotation/cancel-submission// - revert submission

  • View: SalesQuotationSubmissionRevert - views.py:518 (route urls.py:27-31); post() at views.py:532.
  • Auth: IAM + HasPermission (views.py:517-521).
  • Behavior: reverts a submitted-for-approval quotation back to draft; writes notifications, activity log and two Kafka events (views.py:568, 592). Exact reversion status allow-list - partially verified in views.py:532-566, remainder unverified.

8. GET /quotation/list/ - internal list for other modules

  • View: SalesQuotationListForAccounting - views.py:707 (route urls.py:32-36, route name invoice_return_acc).
  • Auth: not IAM - gated by the shared internal password in query param password (helper.validate_internal_pass, views.py:709); returns 400 on bad password.
  • Query params: tenant_id, from_date, to_date, optional entry_status.
  • Behavior: returns non-draft quotations for the tenant in date range, ordered by quotation_date, via SalesQuotationListForACCSerializer (views.py:713-727). Consumed by accounting-side screens.

9. GET /quotation/search/ - list search

  • View: SalesQuotationSearchView (FilteredAPIViewMixin, CustomerDataGatherMixin) - views.py:613 (route urls.py:37).
  • Auth: IAM + HasPermission; action depends on method/context (views.py:625-627).
  • Query params: q (free text), status, page, count, plus customer filter params gathered by the mixin (full filter param list lives in sales/sales_quotation/filters.py + the mixin - unverified here).
  • Response: paginated list via the service's custom transaction pagination (views.py:613).

10. GET /quotation/search/select/ - embedded select search

  • View: SalesQuotationSearchSelectView - views.py:673 (route urls.py:38-42).
  • Auth: IAM only - no feature-permission check (views.py:674), for use in pickers across modules.
  • Behavior: lighter-weight search returning records for selection widgets (views.py:678 onward; response shape via its own select serializer - unverified here).

Frontend usage (apps-frontend @ production)

apps-frontend drives this module from src/services/sales.service.js: list/search via GET_QUOTATIONS = sales/quotation/ + search/?q=..., detail via sales/quotation/detail/{id}/.
