ProductManagement . Stock

Stock ledger and the service-to-service (S2S) inventory protocol. Every managed-inventory product keeps Inventory rows (db_table Inventory) - one per product, or one per batch for batch stock keeping - plus a BatchInventoryTotal row (db_table InventoryTotal) aggregating the batches. Quantities follow three counters: total_quantity, available_quantity, hold_quantity (= total - available). Sales documents hold stock (decrement available at submit, decrement total at approval, restore on cancel); returns and purchase documents add stock. All manipulation and verification endpoints are internal (shared password in the body) and are called by the Sales and Purchase services, which own the journals and notifications - this service only mutates the stock ledger.

All routes below are relative to /api/inventory/; Source: inventory/urls.py, inventory/views.py, inventory/custom_func.py @ edd7d596.

1. POST /create/

  • View: InventoryCreatefromProduct - inventory/views.py:51 (route urls.py:12-14).
  • Auth: no class; body password must equal the shared password (views.py:56-58), else 401.
  • Request: { password, tenant_id, entry_by, product_id, product_stock_keeping, opening_quantity?, rate?, opening_date?, batch_data?: [ { batch_id, opening_quantity, opening_date, rate } ] }.
  • Processing: for batch keeping, one Inventory row per batch (available = total = opening, amount = rate x opening) plus a BatchInventoryTotal row (views.py:59-84); for independent keeping a single Inventory row (views.py:85-95). Called when a product (or its batches) is created.
  • Response: 201 created; 500 on IntegrityError (views.py:99-100).

2. POST /create-endpoint/

  • View: InventoryCreateEndPoint - inventory/views.py:5796 (route urls.py:42-46).
  • Auth: no class; internal password (views.py:5798-5799), else 401.
  • Request: { password, tenant_id, entry_by, product_id, batch_id?, quantity, rate, amount, method }.
  • Processing: creates one Inventory row with total = available = quantity (views.py:5803-5813); when method is grn or invoice, also gets-or-creates the BatchInventoryTotal and adds the quantity to it (views.py:5814-5832).
  • Response: 200; 500 with the exception message on failure (views.py:5835-5838).

3. POST /bulk-create/

  • View: InventoryBulkCreate - inventory/views.py:5883 (route urls.py:11).

Common patterns (all S2S endpoints)

  • Auth: every S2S endpoint gates on the shared internal password in the body (helper.validate_internal_pass / direct comparison against helper.PASSWORD); several fall through silently on auth failure instead of returning 401 (views.py:3563, 3225, 4291, 5585).
  • Movement semantics by entry_status: submit_for_approval moves available only (holds stock); approved commits the movement (total for new stock, both for already-held stock); cancel_submission releases a hold; cancelled reverts a committed movement. Returns and purchases invert the direction (add instead of deduct).
  • Negative stock guard: deductions raise AVAILABLE_NEGATIVE when available (or total) would go below zero, unless the tenant's negative-inventory configuration is on - fetched per request from the Configuration service service-configuration/tenant/expose with configuration_status NEGATIVE_INVENTORY (helper.get_negative_inventory_config, helper.py:146-159).
  • Quantity helpers: custom_func.inventory_ins_increment/decrement (available only) and grn_inventory_ins_increment/decrement (available + total) - inventory/custom_func.py:28-59; item lookup via custom_func.inventory_instance (custom_func.py:10-25).
  • Items are filtered to managed-inventory products before movement (filter_managed_inv_products, imported from dashboard/views.py at inventory/views.py:32).
  • Status codes: 200 on success, 400 on shortage/invalid data, 401 on bad password, 204 when an inventory row does not exist (inconsistent with 404 in the read endpoints - views.py:211-214 vs 2933-2934).

Side effects (all endpoints)

  • Purely local stock-ledger mutations - no journals, no notifications, no Kafka events are raised by the inventory app; the calling Sales / Purchase services own the accounting and messaging side effects.
  • Cross-service reads: the negative-inventory configuration (Configuration service) and, in route 27, the self recent-transactions-internal and product endpoints via async httpx.
