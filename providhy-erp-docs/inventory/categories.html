ProductManagement . Categories

Two-level product category tree (category -> sub-category) per tenant, plus the unit-of-measurement (UOM) master lives in the same product app and is documented with products (products.md). Categories are referenced by products (product_category / product_subcategory FKs) and drive category-based product filtering.

All routes below are relative to /api/product/; Source: product/urls.py, product/views.py, product/serializers.py @ edd7d596.

Endpoint map

# Method Path Purpose Auth
1 GET /category/ List top-level categories (or children of ?category=) IAM + PR902 PRODUCT_CATEGORY view
2 GET /category/search/ Paginated category search (list screen) IAM + PR902 view
3 GET /category/search/select/ Active categories for pickers; injects Fixed Assets pseudo-category IAM only (no-perm)
4 GET /subcategory/search/select/ Active sub-categories of ?parent= for pickers IAM only (no-perm)
5 GET/POST /category/detail/ Category detail / update IAM + PR902 view / add_edit
6 POST /category/inactive/ Bulk activate/deactivate categories IAM + PR902 active_inactive

Legacy note: routes 2 and 3 also accept a versioned suffix (category/search/v2/, category/search/select/v2/ via the <str:version> includes at product/urls.py:206 and :197); with version v2 the parent=None filter is dropped and child_categories are omitted from the response (views.py:448-449, :463-464, :502-503).

1. GET /category/ - list

  • View: ProductCategoryListCreate - product/views.py:347 (route urls.py:25).
  • Auth: IAMAuthenticationBackendProduct + HasPermission; feature PR902 PRODUCT_CATEGORY; GET -> action view (views.py:363-368).
  • Request: query params status (active_status, required - 404 UNKNOWN_STATUS otherwise, views.py:372-375) and optional category (parent id - when present returns that parent's children, else top-level parent=None, views.py:376-385).
  • Processing: tenant-scoped by request.auth (views.py:378-384); paginated with CustomTransactionPagination (views.py:352, 386-388).
  • Response: 200 paginated list via ProductCategorySerializer (recursive child_categories + parent_details, serializers.py:146-179).

2. GET /category/search/ - search

  • View: ProductCategorySearchView - product/views.py:424 (route urls.py:201-210).
  • Auth: IAM + HasPermission, PR902; GET -> view (views.py:431-436).
  • Request: q (free text over unique_id, entry_by, name - icontains, views.py:452-456), status (required, views.py:442-445). Default scope top-level (parent=None) unless version v2 (views.py:447-449).
  • Response: 200 paginated list; v2 omits child_categories (no_return_child context, views.py:462-469).

3. GET /category/search/select/ - picker select

  • View: ProductCategorySearchSelectView - product/views.py:473 (route urls.py:192-200).
  • Auth: IAMAuthenticationBackendProduct only - no HasPermission (no-perm; for cross-module pickers) (views.py:474).
  • Request: q optional, category optional (parent filter, views.py:486-489), return_fixed_asset (bool, views.py:512).
  • Processing: active categories only (views.py:484); on page 1, when return_fixed_asset is true and the query matches "Fixed Assets" (or is empty), a synthetic {id: fixed_asset, name: Fixed Assets} entry is prepended (views.py:510-533).
  • Response: 200 paginated list.

4. GET /subcategory/search/select/ - subcategory picker

  • View: ProductSubCategorySearchSelectView - product/views.py:538 (route urls.py:26-28).
  • Auth: IAM only (no-perm) (views.py:539).
  • Request: parent (category id, required in the filter - views.py:550), q optional.
  • Response: 200 paginated list of active sub-categories.

5. GET/POST /category/detail// - detail & update

  • View: ProductCategoryUpdate - product/views.py:568 (route urls.py:29-33).
  • Auth: IAM + HasPermission, PR902; GET -> view, POST -> add_edit (views.py:583-588).
  • GET: tenant-scoped lookup with prefetch of children + parent (views.py:590-596); 200 serializer data, 404 CATEGORY_NOT_FOUND (views.py:598-606).
  • POST: body { name, parent? }. Guards: 404 when missing; 400 INACTIVE_RECORD_NO_UPDATE when the record is inactive (views.py:616-620); 400 when parent == pk (SAME_PARENT_CHILD_CATEGORY, views.py:622-623); a category with no existing parent cannot become a sub-category, and a category that already has children cannot become one either (CANNOT_BE_SUBCATEGORY, views.py:629-645); parent id must exist (views.py:647-648).
  • Processing: serializer ProductCategorySerializer - case-insensitive duplicate check within the same parent (serializers.py:94-116), name sanitization via Configuration service (sanitize_main_data -> POST {CONFIGURATION}api/sanitization/form-data/, serializers.py:85-92, helper.py:102), activity log on change (views.py:659-661).
  • Response: 200 { message }; 400 on validation errors.

6. POST /category/inactive/ - bulk status

  • View: ProductCategoryBulkActiveStatusUpdate - product/views.py:674 (route urls.py:34-38).
  • Auth: IAM + HasPermission, PR902; POST -> action active_inactive (views.py:692-699).
  • Request: { id: [ids], status: active|inactive } - validated as dict with list id (views.py:709-715).
  • Processing: per-item tenant-scoped update inside transaction.atomic; missing id -> 404 PCATEGORY_NOT_FOUND (views.py:729-732); activity log per item (views.py:723-728).
  • Response: 200 { message }.

Side effects (all endpoints)

  • Activity log via Events service (POST {EVENTS}api/activity_log/create-activity-log/ - helper.py:100) for create/update/active-inactive.
  • Name sanitization call to the Configuration service on every create/update (helper.py:102); a failed sanitize aborts the write (SANITIZE_ERROR).

Frontend usage (apps-frontend @ production)

Per fe_usage.json, none of the category routes are referenced directly by the frontend apps (all listed under unusedLatest) - a floor, not a ceiling; category picks are likely served through the search/select endpoints from ERP screens not captured by the scan, or the module is driven by other services.

Superseded / legacy routes (not documented)

  • None in this area (the <str:version> suffix variants of routes 2-3 are the same views, documented above).
