ProductManagement . Campaigns

Time-boxed product campaigns (discount/value rules applied to a product during a from_date..to_date window). A campaign is a JSON of line items (value field) attached to a product via the product_campaign FK on Product (product/models.py:130-132). Campaigns are consumed by Sales/ERP screens through the internal check endpoints.

All routes below are relative to /api/product/; Source: product/urls.py, product/views.py, product/serializers.py @ edd7d596.

Endpoint map

# Method Path Purpose Auth
1 GET /campaign/ List campaigns by status IAM + PR905 PRODUCT_CAMPAIGN view
2 GET /campaign/search/ Paginated campaign search (list screen) IAM + PR905 view
3 GET /campaign/search/select/ Active in-window campaigns for pickers IAM only (no-perm)
4 POST /campaign/ Create campaign IAM + PR905 add_edit
5 GET/POST /campaign/detail/ Campaign detail / update IAM + PR905 view / add_edit
6 POST /campaign/inactive/ Bulk activate/deactivate IAM + PR905 active_inactive
7 POST /campaign/check/ Is this campaign active today? (S2S) internal password
8 POST /campaign-data/ Campaign of a product, if in window (S2S) internal password

1. GET /campaign/ - list

  • View: CampaignListCreate - product/views.py:2611 (route urls.py:142).
  • Auth: IAM + HasPermission, PR905; GET -> view (views.py:2627-2632).
  • Request: status (required, views.py:2636-2639).
  • Response: 200 paginated list via CampaignSerializer (views.py:2640-2645).

2. GET /campaign/search/ - search

  • View: CampaignSearchView - product/views.py:2530 (route urls.py:153-155).
  • Auth: IAM + HasPermission, PR905; GET -> view (views.py:2537-2542).
  • Request: q (icontains over name, entry_by, unique_id - views.py:2558-2566), status (required, views.py:2548-2551).
  • Response: 200 paginated list.

3. GET /campaign/search/select/ - picker select

  • View: CampaignSearchSelectView - product/views.py:2575 (route urls.py:156-160).
  • Auth: IAM only (no-perm) (views.py:2576).
  • Processing: active campaigns whose window covers today (from_date <= now <= to_date, views.py:2589-2593); q optional over name/entry_by/unique_id.
  • Response: 200 paginated list via CampaignSearchSerializer (serializers.py:1116-1119).

4. POST /campaign/ - create

  • View: CampaignListCreate.post - views.py:2647-2670 (route urls.py:142).
  • Auth: IAM + PR905; POST -> add_edit (views.py:2627-2632).
  • Request: name (required), from_date (date, required), to_date (date, required), type (required - CampaignType, dashboard/choices.py:78), value (array, required and non-empty, views.py:2651-2655). value is the campaign line items (quantity/price style rows; serializer sorts by quantity, serializers.py:237-239).
  • Processing: CampaignSerializer.create - sanitizes header + line items via Configuration service (serializers.py:187-225, 231-233), case-insensitive name uniqueness per tenant (serializers.py:235-236, helper.is_unique). Activity log on create (views.py:2666).
  • Response: 201 serializer data; 400 INVALID_OBJECT on validation failure (views.py:2668-2670).

5. GET/POST /campaign/detail// - detail & update

  • View: CampaignUpdate - product/views.py:2674 (route urls.py:143-147).
  • Auth: IAM + PR905; GET -> view, POST -> add_edit (views.py:2689-2694).
  • GET: 200 serializer data; missing -> CAMPAIGN_NOT_FOUND raised as ValidationError (views.py:2696-2705) - note: surfaces as a validation error, not a plain 404 (views.py:2700).
  • POST: same required fields as create (views.py:2719-2723); 400 INACTIVE_RECORD_NO_UPDATE when inactive (views.py:2714-2718); same sanitize + uniqueness processing as create (serializers.py:242-250); activity log with changed fields (views.py:2727-2729).
  • Response: 200 serializer data.

6. POST /campaign/inactive/ - bulk status

  • View: CampaignBulkActiveStatusUpdate - product/views.py:2737 (route urls.py:148-152).
  • Auth: IAM + PR905; POST -> active_inactive (views.py:2755-2762).
  • Request: { id: [ids], status } (views.py:2772-2778); missing id -> 404 CAMPAIGN_NOT_FOUND (views.py:2792-2795).
  • Processing: per-item update in transaction; activity log per item (views.py:2787-2791).
  • Response: 200 { message }.

7. POST /campaign/check/ - S2S active check

  • View: CampaignCheck - product/views.py:3242 (route urls.py:161).
  • Auth: internal - body password must equal INTERNAL_PASS (views.py:3247, helper.py:34); no DRF auth class (note the misspelled permisson_classes = [AllowAny] at views.py:3243, which DRF ignores).
  • Request: { password, campaign_id, tenant_id }.
  • Response: 200 campaign serializer data when the campaign exists and its window covers today (views.py:3248-3255); 204 when no such campaign (views.py:3258-3259); 401 invalid password; 500 on unexpected error (views.py:3265-3273).

8. POST /campaign-data/ - S2S product campaign

  • View: ProductCampaignData - product/views.py:3687 (route urls.py:162).
  • Auth: internal - helper.validate_internal_pass on body password (views.py:3689); 401 on failure (views.py:3708-3709).
  • Request: { password, product_id, tenant_id }.
  • Response: 200 campaign data when the product has a campaign and the window covers today (views.py:3695-3702); 404 when no product / no campaign / out of window (views.py:3703-3707).

Side effects

  • Activity log via Events service for create/update/bulk-status (helper.py:100).
  • Configuration service sanitize calls on every create/update (helper.py:102).
  • No Kafka or notification calls in the campaign views (verified by inspection of views.py:2530-2802, :3242-3276, :3687-3711).

Frontend usage (apps-frontend @ production)

Per fe_usage.json, all eight campaign routes are unused by the frontend apps (all listed under unusedLatest) - a floor, not a ceiling; the campaign UI may be served from a screen not captured by the scan.
