ERP-ProjectMaster . Dashboard

The dashboard area hosts the ERP home-screen approval widget, static choice lists, the global cross-service search, tenant-level data deletion, and the internal reporting / reconciliation / opening-details endpoints that other ProvidhyERP services call with the shared internal password. Routes live in dashboard/urls.py and views in dashboard/views.py.

Endpoint map

1. system-choices/

  • View: SystemChoiceView, dashboard/views.py:55-82; route dashboard/urls.py:8.
  • Auth: public - AllowAny (dashboard/views.py:56).
  • Request: no body (GET).
  • Response: 200 with four choice lists built from dashboard/choices.py - payment_method (choices.py:38-41), activation_status (choices.py:33-35), customer_supplier (choices.py:44-47), cr_dr (choices.py:50-52).
  • Side effects: none.

2. service-choices/

  • View: ServiceChoiceView, dashboard/views.py:85-105; route dashboard/urls.py:9.
  • Auth: public - no authentication or permission classes are set.
  • Request: no body (GET).
  • Response: 200 with service (choices.ServiceChoices, dashboard/choices.py:73-101), features_list (choices.AllFeatures, dashboard/choices.py:104-220), main_module_list (choices.MainModule, dashboard/choices.py:22-30).
  • Side effects: none.

3. analytics/

  • View: DashboardContent, dashboard/views.py:108-170; route dashboard/urls.py:10.
  • Auth: IAM via IAMAuthenticationBackendSupplier (dashboard/views.py:109) - requires the SUPPLIER_MASTER PR200 subscription (dashboard/auth_backends.py:77-81); no feature/action permission check (no-perm IAM variant).
  • Request: no body (GET); tenant, user and username come from the token.
  • Processing: makes four sequential GET calls with tenant_id/user_id/username/password params to the purchase invoice approval-list (dashboard/helper.py:91), sales invoice approval-list (dashboard/helper.py:94), inventory approval-list (dashboard/helper.py:106) and accounting journal-voucher approval-list (dashboard/helper.py:88) endpoints (dashboard/views.py:120-160).
  • Response: 200 with the four response bodies keyed inventory, purchase, sales, accounting (dashboard/views.py:163-169); a non-200 upstream simply contributes null.
  • Side effects: none.

4. tenant-data-deletion/

  • View: TenantDataDeletion, dashboard/views.py:173-200; route dashboard/urls.py:11.
  • Auth: internal - view-level password gate, 401 on mismatch (dashboard/views.py:175-176, dashboard/helper.py:125-128).
  • Request (JSON): tenant_id (string, number or list, required, dashboard/views.py:179-184), password.
  • Processing: inside transaction.atomic (dashboard/views.py:178) deletes all rows of the tenant(s) from the ID sequence model, Customer, CustomerCategory, Supplier, SupplierCategory, Employee, PaymentTerm and ActionModel tables (dashboard/views.py:186-197).
  • Response: 200 Data Deleted Successfully; missing tenant_id gives a 200 with Invalid Tenant id (dashboard/views.py:180-181); 401 on bad password.
  • Side effects: irreversible master-data deletion for the tenant; no activity log, no notification.

5. supplier-customer-payment/

  • View: SupplierCustomerPayment, dashboard/views.py:203-272; route dashboard/urls.py:12-16.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:204, dashboard/auth_backends.py:157-163).
  • Request: GET query params tenant_id, entity_id, entity_type (supplier or customer, dashboard/views.py:206-209); POST JSON adds remaining_amount (dashboard/views.py:241-243).
  • Processing: GET serializes the party with SupplierCustomSerializer or CustomerCustomSerializer (dashboard/views.py:215-224); POST overwrites the party's remain_opening and saves (dashboard/views.py:267-268).
  • Response: GET 200 party object, 400 Invalid entity type, 404 Entity not found (dashboard/views.py:225-233); POST 200 Remaining amount updated successfully (dashboard/views.py:269-271).
  • Side effects: POST mutates remain_opening directly; no Kafka, no activity log.

6. get-tenants-supplier-customer-opening-details/

  • View: GetTenantSupplierCustomerOpeningDetails, dashboard/views.py:275-298; route dashboard/urls.py:17-21.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:276).
  • Request (JSON): tenant_id (list, required), password (dashboard/views.py:279-281).
  • Response: 200 map of tenant_id to supplier and customer lists of id, unique_id, opening, opening_cr_dr, opening_date (dashboard/views.py:288-298).
  • Side effects: none (read-only).

7. update-tenants-supplier-customer-opening-details/

  • View: UpdateTenantSupplierCustomerOpeningDetails, dashboard/views.py:301-466; route dashboard/urls.py:22-26.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:302).
  • Request (JSON): parties_data - map of tenant_id to fy_id plus supplier/customer arrays (dashboard/views.py:399-405) - and password.
  • Processing: skips a tenant when an ActionModel closing marker for that fy_id already exists (dashboard/views.py:406-415, dashboard/choices.py:328-332); per entity updates opening_cr_dr, opening, remain_opening and the later opening_date (dashboard/views.py:369-397); bulk_updates then bulk-creates SUPPLIER_CLOSING / CUSTOMER_CLOSING ActionModel markers, all inside transaction.atomic (dashboard/views.py:416-461).
  • Response: 200 Opening Info updated successfully (dashboard/views.py:463-466).
  • Side effects: fiscal-year closing markers make later re-runs for the same FY no-ops; no activity log.

8. get-tenants-supplier-customer-details/

  • View: GetTenantSupplierCustomerDetails, dashboard/views.py:469-490; route dashboard/urls.py:27-31.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:470).
  • Request (JSON): tenant_id, entity_id (list of unique_ids, must be a list, dashboard/views.py:473-479), password.
  • Response: 200 merged customer and supplier rows of id, unique_id, name, pan_number (dashboard/views.py:481-489).
  • Side effects: none.

9. supplier-customer-for-analytics/

  • View: SupplierAndCustomerForAnalytics, dashboard/views.py:493-527; route dashboard/urls.py:32-36.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:494).
  • Request (JSON): tenant_id (required), and at least one of supplier or customer id lists (dashboard/views.py:497-510).
  • Response: 200 with supplier and customer maps of id to name (dashboard/views.py:522-525); 400 otherwise.
  • Side effects: none.

10. search-global/

  • View: GlobalSearchAPIView, dashboard/views.py:530-761; route dashboard/urls.py:37-41.
  • Auth: IAM via the bare IAMAuthenticationBackend (dashboard/views.py:531) - no subscription or feature check (no-perm IAM variant).
  • Request: GET query param q (required, dashboard/views.py:743).
  • Processing: in parallel (dashboard/views.py:700-708) - (a) trigram search of the tenant's Customer and Supplier names via pg_trgm with type inferred from the CUS/SUP unique_id prefix (dashboard/views.py:575-624), (b) POSTs q with the internal password to Reporting api/dashboard/choices-internal/ (dashboard/helper.py:111), Accounting api/dashboard/search-global/ (dashboard/helper.py:115) and ProductManagement api/product/search-global/ (dashboard/helper.py:113) (dashboard/views.py:535-539, 626-655), (c) keyword similarity match against SearchableFeatures (dashboard/views.py:657-698, dashboard/choices.py:223-266).
  • Response: 200 with other (top 5 merged, similarity-sorted, dashboard/views.py:757-761) and report_name lists; 500 on search failure (dashboard/views.py:750-755).
  • Side effects: none (read-only, fan-out to 3 services).

11. get-tenants-supplier-customer-list/

  • View: GetTenantSupplierCustomerListforReporting, dashboard/views.py:800-862; route dashboard/urls.py:42-46.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:801).
  • Request: GET query params tenant_id and password (both required, dashboard/views.py:804-812).
  • Response: 200 with supplier, customer and employee lists carrying id, unique_id, name, opening, opening_cr_dr, gl_mapping, opening_date, pan_number, remain_opening (dashboard/views.py:817-860).
  • Side effects: none.

12. check-reconciliation/

  • View: SupplierCustomerCheckReportReconcileAPIView, dashboard/views.py:764-797; route dashboard/urls.py:47-51.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:765).
  • Request (JSON): tenant_id (required, dashboard/views.py:777-783).
  • Response: 200 with tenant_id and data containing the full supplier and customer lists serialized by SupplierListSerializerForACC / CustomerListSerializerForACC (dashboard/views.py:767-789).
  • Side effects: none.

13. get-tenants-supplier-customer-list/ (duplicate mount)

  • View: same GetTenantSupplierCustomerListforReporting, dashboard/views.py:800; mounted a second time at dashboard/urls.py:52-56 with the same name.
  • Auth: internal (same as #11).
  • Request / Response / Side effects: identical to #11. The duplicate path entry is unreachable - Django resolves the first matching pattern (dashboard/urls.py:42), so this mount never serves a request. Cataloged as a separate route; no behavior difference.

14. recent-transactions/<str:party_type>/<int:party_id>/

  • View: PartyRecentTransactionsView, dashboard/views.py:865-946; route dashboard/urls.py:57-61.
  • Auth: IAM via the bare IAMAuthenticationBackend (dashboard/views.py:866) - no feature check (no-perm IAM variant).
  • Request: path params party_type (customer or supplier) and party_id (dashboard/views.py:925-936); anything else is 404.
  • Processing: the party is looked up by id without a tenant filter (dashboard/views.py:930-934); when the party is flagged as the other party type (as_supplier / as_customer) both sources are fetched, else only the matching one - POST with the internal password to Sales api/dashboard/sales-recent-txn-party/ (dashboard/helper.py:118) and/or Purchase api/dashboard/purchase-recent-txn-party/ (dashboard/helper.py:119) (dashboard/views.py:868-907).
  • Response: 200 with up to 5 transactions sorted newest first (dashboard/views.py:938-946).
  • Side effects: none. Observation: the party lookup is not tenant-scoped (dashboard/views.py:930-934), so a party id from another tenant that resolves to this tenant's user token still returns that party's transaction list - unverified whether upstream endpoints re-check the tenant.

15. party-check/

  • View: PartyCheckView, dashboard/views.py:949-985; route dashboard/urls.py:62-66.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:950).
  • Request (JSON): party_data with supplier_ids and customer_ids, tenant_id (required, dashboard/views.py:953-965); optional return_fields (default id, name, pan_number, dashboard/views.py:958-962).
  • Response: 200 with supplier and customer maps of id to record (dashboard/views.py:967-985).
  • Side effects: none.

16. list-party-internal/

  • View: ListPartyInternalView, dashboard/views.py:988-1036; route dashboard/urls.py:67-71.
  • Auth: internal - InternalRequestPermission (dashboard/views.py:989).
  • Request (JSON): tenant_id (required, 400 when missing, dashboard/views.py:1006-1013), optional q and count (dashboard/views.py:1007-1008).
  • Processing: searches active suppliers and customers by name / unique_id / entry_by and concatenates the two serialized lists, slicing to count (dashboard/views.py:992-1035). The pagination attribute (dashboard/views.py:990) is not applied to the response.
  • Response: 200 merged list (dashboard/views.py:1036).
  • Side effects: none.

17. log-viewer/

  • View: LogViewerAPIView, dashboard/views.py:1039-1093; route dashboard/urls.py:72-76.
  • Auth: public in the sense of no IAM - DRF BasicAuthentication plus IsAdminUser (dashboard/views.py:1040-1041); only Django admin users pass. The consuming UI is not part of this codebase (unverified).
  • Request: GET query params file_name (default app.log), limit (default 100), position (first or last), order (asc or desc) (dashboard/views.py:1044-1047).
  • Processing: reads .log/.txt files from LOG_DIR (core/settings.py:198) and renders them into the logs/log_viewer.html template (dashboard/views.py:1049-1092).
  • Response: HTML log viewer; 404 JSON with the available log files when the named file does not exist (dashboard/views.py:1060-1063).
  • Side effects: none.
