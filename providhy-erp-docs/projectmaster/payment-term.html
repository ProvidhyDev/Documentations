ERP-ProjectMaster . Payment Term

Payment terms define the credit periods used by supplier and customer records. The area covers CRUD with IAM permission checks, bulk activate/deactivate, and several internal endpoints used by other services (check, ageing summary, tenant lists) plus a bulk default-term migration endpoint. Routes live in payment_term/urls.py, views in payment_term/views.py, serializers in payment_term/serializers.py.

Endpoint map

1. transfer-payment-term/

  • View: DefaultPaymentTermView, payment_term/views.py:141-331; route payment_term/urls.py:6-10.
  • Auth: public - no authentication classes and no permission class are set; an InternalRequestPermission decorator was commented out above the old implementation (payment_term/views.py:29). Why this write endpoint is intentionally unauthenticated is unverified.
  • Request (JSON): tenant_id (list) and data - map of credit_period to title / description (payment_term/views.py:166-168, 141-159 docstring).
  • Processing: per tenant: skip when the title already exists in any case form (payment_term/views.py:261-264); otherwise rename the most recent term of that credit_period and mark it default + active (payment_term/views.py:286-291); otherwise create a new PaymentTerm with a PTM-prefixed unique_id minted from the ID sequence model (payment_term/views.py:293-313). All writes are bulk operations inside one transaction (payment_term/views.py:318-331).
  • Response: 200 Default payment terms updated successfully (payment_term/views.py:189-192); 400 when tenant_ids or data are missing (payment_term/views.py:197-203).
  • Side effects: mutates or creates PaymentTerm rows and ID sequence rows for the given tenants.

2. / (list-create)

  • View: PaymentTermListCreate, payment_term/views.py:334-385; route payment_term/urls.py:11.
  • Auth: IAM - IAMAuthenticationBackendPaymentTerm (payment_term/views.py:336, subscription PR500, dashboard/auth_backends.py:101-105) plus HasPermission with feature PAYMENT_TERM_CREATION PR501 (payment_term/views.py:337); action add_edit for POST (payment_term/views.py:341-344). No get method is implemented, so GET returns 405.
  • Request (JSON): title and credit_period are required (payment_term/views.py:360); serializer fields also include description, default, active_status (payment_term/serializers.py).
  • Processing: inside transaction.atomic; create injects tenant_id and entry_by, calls Configuration sanitization (payment_term/serializers.py:39-42, dashboard/helper.py:83) and enforces tenant-scoped unique title (payment_term/serializers.py:43-45, dashboard/helper.py:150-170) (payment_term/views.py:358-368).
  • Response: 201 with id, title, unique_id, message (payment_term/views.py:372-380); 400 on invalid data (payment_term/views.py:382-385).
  • Side effects: activity log CREATION to Events (payment_term/views.py:349-356, 371, dashboard/activity_log.py:13-31).

3. detail/<int:pk>/

  • View: PaymentTermUpdate, payment_term/views.py:388-458; route payment_term/urls.py:12-16.
  • Auth: IAM - same backend as #2 (payment_term/views.py:390); feature PR501 (payment_term/views.py:391); action view for GET, add_edit for POST (payment_term/views.py:394-400).
  • Request: path param pk; POST JSON requires title and credit_period (payment_term/views.py:439).
  • Processing: lookup scoped to the requesting tenant (payment_term/views.py:402-406); POST refuses inactive records (payment_term/views.py:432-433); update keeps the tenant-scoped unique title (payment_term/serializers.py:47-57) and computes field diffs for the edit log (payment_term/views.py:444, dashboard/activity_log.py:34-42).
  • Response: GET 200 serialized term or 404 with nested error Payemnt Term not found (payment_term/views.py:418-427); POST 200 with id and message (payment_term/views.py:447-453) or 400 (payment_term/views.py:455-458).
  • Side effects: activity log EDITION on update (payment_term/views.py:408-416, 446).

4. inactive/

  • View: PaymentTermBulkActiveStatusUpdate, payment_term/views.py:461-529; route payment_term/urls.py:17-21.
  • Auth: IAM - IAMAuthenticationBackendPaymentTerm (payment_term/views.py:463); feature PR501 (payment_term/views.py:465); action active_inactive for POST (payment_term/views.py:468-473).
  • Request (JSON): id (list of term ids) and status (active or inactive) (payment_term/views.py:497-506).
  • Processing: inside transaction.atomic, sets active_status on each term (payment_term/views.py:501-508).
  • Response: 200 with status message (payment_term/views.py:520-526); 404 when an id does not exist (payment_term/views.py:514-517); 400 (Unknown request) on empty body (payment_term/views.py:528-529, dashboard/helper.py:340).
  • Side effects: activity log ACTIVE/INACTIVE per record (payment_term/views.py:484-495, 509-513).

5. check/

  • View: PaymentTermCheck, payment_term/views.py:532-549; route payment_term/urls.py:22.
  • Auth: internal - view-level password gate (payment_term/views.py:539, dashboard/helper.py:125-128). The class declares a misspelled permisson_classes attribute, so no permission class is actually applied and DRF defaults (AllowAny) govern (payment_term/views.py:533).
  • Request (JSON): password, tenant_id, payment_term_id (payment_term/views.py:536-538).
  • Response: 200 with the full serialized term (payment_term/views.py:544-545); 404 when the term does not exist (payment_term/views.py:546-547); 401 on bad password (payment_term/views.py:548-549).
  • Side effects: none. This endpoint is also called by this service itself when creating or editing a party that carries a payment_term (dashboard/helper.py:74, 131-139).

6. search/

  • View: PaymentTermSearchView, payment_term/views.py:552-595; route payment_term/urls.py:23.
  • Auth: IAM - IAMAuthenticationBackendPaymentTerm (payment_term/views.py:554) plus HasPermission with feature PR501 and action view (payment_term/views.py:552-557, 559-565).
  • Request: GET query params q (optional) and status (required; 404 when not active/inactive, payment_term/views.py:572-574).
  • Processing: case-insensitive search over title, entry_by, unique_id (payment_term/views.py:581-587), paginated at 100 per page (payment_term/views.py:591-595, dashboard/pagination.py:4-7).
  • Response: paginated list of serialized terms (payment_term/views.py:592-595).
  • Side effects: none.

7. search/select/

  • View: PaymentTermSearchSelectView, payment_term/views.py:598-625; route payment_term/urls.py:24-28.
  • Auth: IAM via IAMAuthenticationBackendPaymentTerm (payment_term/views.py:599) - subscription check only, no feature/action permission (no-perm IAM variant).
  • Request: GET query param q (optional) (payment_term/views.py:604).
  • Processing: active terms only (payment_term/views.py:607-610), icontains over title, entry_by, unique_id (payment_term/views.py:612-620), paginated.
  • Response: paginated list of serialized terms (payment_term/views.py:621-625).
  • Side effects: none.

8. all-payment-term/

  • View: AllPaymentTermView, payment_term/views.py:649-664; route payment_term/urls.py:29-31.
  • Auth: internal - view-level password gate (payment_term/views.py:654-658); no permission class set.
  • Request (JSON): password (payment_term/views.py:654).
  • Response: 200 map of tenant_id to lists of id and credit_period for every payment term of every tenant (payment_term/views.py:659-664); 401 Invalid Password on bad password.
  • Side effects: none. Cross-tenant read: returns data of all tenants in one response.

9. payment-term-for-ageing/

  • View: PaymentTermForAgeingSummary, payment_term/views.py:667-680; route payment_term/urls.py:32-36.
  • Auth: internal - InternalRequestPermission (payment_term/views.py:668).
  • Request (JSON): tenant_id (required, 400 when missing, payment_term/views.py:671-674) and payment_term (list of ids, payment_term/views.py:672).
  • Response: 200 map of id to credit_period (payment_term/views.py:676-680).
  • Side effects: none.

10. tenant-list/

  • View: ListPaymentTermTenantView, payment_term/views.py:683-706; route payment_term/urls.py:37.
  • Auth: internal - InternalRequestPermission (payment_term/views.py:684).
  • Request (JSON): tenant_id (required, payment_term/views.py:687), optional payment_term_ids (list) and return_type (payment_term/views.py:690-691).
  • Response: 200 - either the list of id/credit_period rows when return_type is list, or a map of id to the row (payment_term/views.py:697-706).
  • Side effects: none.

Superseded / legacy routes

(none in the catalog). Legacy code in this area: the old per-tenant DefaultPaymentTermView implementation is fully commented out (payment_term/views.py:29-129), and BulkPaymentTermView (payment_term/views.py:628-646) exists but is not mounted in payment_term/urls.py, so it has no route.
