Kafka Infrastructure

The event backbone of Providhy ERP: every module service publishes record events (create/approve/cancel/reject of vouchers, invoices, stock moves, master data) to Kafka; the reporting service consumes them into a read-optimized warehouse; providhy-kafka is the broker cluster (kafka-crs:9092, SASL enabled in Reporting/settings.py:203-209).

Repos

Repo Role HTTP surface
providhy-kafka broker cluster (kafka-crs) none (broker only)
Kafka-Producer producer client library used by module services none (library)
Kafka-Consumer consumer management-command host /admin/ (Django admin only)

Catalogs: Kafka-Consumer.json (1 route: /admin/), Kafka-Producer.json (0 routes), providhy-kafka.json (0 routes). All three are non-HTTP infrastructure, so they are documented here instead of as endpoint pages.

Topics

Four record-event topics, one per business area, created by a daily Celery beat task in Reporting/celery.py:14-19 (dashboard/tasks.py:23, 28-47) if missing:

  • sales_events
  • purchase_events
  • inventory_events
  • accounting_events

Message key = module (sales / purchase / inventory / accounting / master) selects the handler in dashboard/management/commands/kafka_consumer.py:106-118; the action field is matched against ConsumerActionList (dashboard/choices.py:644-821).

Consumer (reporting)

  • Command kafka_consumer.py (group reporting-consumer-group, auto.offset.reset earliest, bootstrap KAFKA_BROKER_URL; settings at Reporting/settings.py:199-209; topic list from the KAFKA_TOPICS env var, kafka_consumer.py:74-93).
  • Effects: materialize approved/cancelled/submitted/rejected records into the transaction views (SalesTransactionView, PurchaseTransactionView, ProductTransactionView, AccountingTransactionView) and the ledger via dashboard/kafka_data_ingestor.py (create_* / cancel_* / reject_* variants); product create/edit + new-batch records populate product master materialized data.
  • Verified line citations: see reporting overview section Kafka consumption.

Producers (module services)

  • Each module's helper publishes record events on state transitions (e.g. Sales dashboard/custom_functions.py after voucher state changes; Accounting voucher status changes; ProductManagement product/batch creation).
  • In-process producer classes KafkaProducerService / KafkaProducerServiceSASL (Reporting/dashboard/producer.py:8-42) are used by reporting's own kafka-test endpoints; module services use the shared producer library (Kafka-Producer repo) with the same SASL settings.
  • The events service additionally carries notifications/activity logs out-of-band over HTTP (see events): Kafka carries the record data, events carries the human-facing trail.

Frontend usage

None - infrastructure only.
